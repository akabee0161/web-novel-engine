- 状態: **暫定**。実装前であり、確定していない

  **台本に出てこない命令は載せない**

この一覧は「あったら便利そうな機能」ではなく「実際に台本が要求した機能」だけを記録している。
台本を書き足した結果として必要になった命令だけを、ここに追加していく。

## 第一原則

**無記号のプレーンテキストが、そのままで最小の台本として成立すること。**

記法なしの原稿がパースエラーになってはならない。演出はすべて後付けの差分である。

## 行頭記号

| 記号 | 意味 |
|---|---|
| `#` | コメント |
| `=` | シーン宣言 |
| `@` | 演出指示 |
| `>` | 話者（次の1ブロックのみ有効） |

これ以外で始まる行はすべて本文。

## テキストの種類

| 書き方 | ネームプレート | 用途 |
|---|---|---|
| 記号なしの行 | 出さない | 地の文、主人公のモノローグ |
| `「…」` | `@protagonist` の名前 | 主人公の発話 |
| `>名前` の直後の `「…」` | その名前 | 他の人物の発話 |
| `>` （引数なし）の直後 | 出さない | 話者を伏せる |

`「」` は制御文字ではない。約物として本文中で自由に使える。

```
ミカは「うん」とだけ言って、椅子に座り直した。
```

行頭が `「` でないため地の文として扱われる。

### 話者の指定

`>` の引数は**キャラクターIDではなく表示名そのもの**。事前登録は不要。

```
>ミカ
「おつかれ。刷り上がったよ」

>？？？
「読んでくれた?」
```

叙述トリックのために実名を伏せる用途をそのまま書ける。
その代償として誤字が検出できない（未解決の論点を参照）。

`>` は**直後の1ブロックにのみ**効く。状態を持たないため、
行の挿入・移動・切り取りで話者の解釈が変わらない。

## シーン宣言

```
= scene 部室・放課後
```

シーンはセーブ位置の座標であり、復元時のリプレイ開始点。
詳細は [初期要件と保存設計](specs/2026-08-07-initial-requirements-and-save-design.md) を参照。

## 命令一覧

### 作品メタ

| 記法 | 用途 |
|---|---|
| `@title <文字列>` | 作品タイトル |
| `@protagonist <表示名>` | 主人公のネームプレート表示名 |

### 背景・音

| 記法 | 用途 |
|---|---|
| `@bg <名前> [fade:<ms>]` | 背景切替 |
| `@bgm <名前>` | BGM 開始 |
| `@bgm stop [fade:<ms>]` | BGM 停止 |
| `@se <名前>` | 効果音 |

### 立ち絵

| 記法 | 用途 |
|---|---|
| `@show <キャラ> <表情> pos:<位置>` | 表示・表情変更 |
| `@move <キャラ> pos:<位置>` | 位置移動 |
| `@hide <キャラ>` | 退場 |

### 進行・演出

| 記法 | 用途 |
|---|---|
| `@wait <ms>` | 間 |
| `@speed slow` / `@speed normal` | 文字送り速度 |
| `@flashback on` / `@flashback off` | 回想の画面効果 |

## 未解決の論点

叩き台を書いた結果として見つかった問題。実装前に方針を決める必要がある。

1. **シーン境界での状態継承が未定義。**
   シーンに入ったとき、立ち絵・背景・BGM は持ち越されるのか、リセットされるのか。
   セーブのシーン入口スナップショットが何を含むかに直結する。

2. **`@show` と `@move` が重複している。**
   `@show <キャラ> <表情> pos:<位置>` も `@move <キャラ> pos:<位置>` も位置を変える。
   `@show` に統合できる可能性がある。

3. **`@speed` / `@flashback` の作用範囲。**
   明示的に戻す設計だと戻し忘れる。「次の1ブロックのみ」にするか、範囲指定にするか。

4. **本文ブロックの区切り規則が未定。**
   叩き台では本文をすべて空行で区切っており、連続する非空行の扱いを回避している。
   本文ブロックはセーブの連番の単位なので、曖昧なままにできない。

5. **話者名の誤字が検出できない。**
   `>ミカ` と `>ミク` を打ち間違えてもエラーにならない。
   「1回しか出現しない話者名」を lint で警告する等の緩和が要る。

6. **話者が付いていないセリフの検出。**
   話者なしは仕様上正しい（主人公の発話）ため、付け忘れがエラーにならない。
   後から話者を足す運用を前提にするなら、ビルド時に一覧を出す lint が要る。
