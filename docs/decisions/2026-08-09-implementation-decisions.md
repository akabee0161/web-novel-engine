- 位置づけ: 決定記録。**この文書は書き換えない。** 仕様が変わったら新しい記録を足す

着手前に確定させた10項目は[2026-08-08 の記録](2026-08-08-pre-implementation-decisions.md)にある。

## 1. 再生ループは世代で打ち切る

**決定:** `Runtime` に `generation` を持ち、`load()` は `abortRun()` で世代を進めてから
新しい再生を始める。`runFrom` は step を1つ実行するたびに世代を確認し、
変わっていたら黙って降りる。

**なぜ:** 計画の `load()` は走っている再生ループを止めていなかった。
クリック待ちの状態でロードすると `runFrom` が二重に走り、
古いループが次のクリックで状態を元の位置へ引き戻す。

**打ち切る側は待ちも解く必要がある。** 世代を進めただけでは、古いループは
`waitForClick` の中で止まったままで判定に到達しない。
`abortRun()` が `clickResolve` と `performCancel` を呼ぶのはこのため。

**制約として残したもの:** `load()` を呼んでよいのは「クリック待ち」か
「まだ再生を始めていない」ときだけ。文字送りの最中に呼ぶと、
打ち切られた側の文字送りが `visibleChars` を上書きしうる。
UI は `canOpenUi()` でこれを塞いでいるが、型では守られていない。

## 2. ページの判定は高さではなく行数で行う

**決定:** `computePageBreaks` は `range.getClientRects().length` を
`floor(枠の高さ / line-height)` と比べる。

**なぜ:** 計画は Range の矩形高さを要素の `clientHeight` と比べていたが、
**Range の矩形はグリフの範囲であって行送りを含まない。**
最終行の行送りぶん（line-height − 文字の高さ）だけ判定が甘くなり、枠から1行はみ出す。
実測では「2行 = 224px」が「192px に収まる」と判定され、分割が起きなかった。

高さ同士に見えて尺度が違う。行数で比べれば両辺が同じ尺度になる。

---

## 3. 画面サイズの変更は次の本文ブロックから反映する

**決定:** `setPageBreaks()` が意味を持つのは `isWaitingForPageBreaks()` が true のあいだだけ。
本文の途中で受け取った境界は無視する。resize での再測定は行わない。

**なぜ:** 本文の途中で区切りが変わると、`type()` が走り終えた文字範囲と
表示する文字範囲が食い違って表示が壊れる。
「読んでいた文字がどのページに移ったか」の正解も一意に決まらない。

**却下した案:** ページのループが毎回 `view.pageBreaks` を読み直す。
現在ページの番号が指す位置がずれるため、結局同じ問題を別の場所に移すだけになる。

読者がブロックの途中で画面を回す頻度と、壊れた表示を出す損失を比べて、
**次のブロックまで待たせるほうを採った。**

---

## 4. 測定待ちは「本文」ではなく「待っているか」で駆動する

**決定:** UI の測定は依存配列を持たない `useLayoutEffect` で行い、
毎レンダで `runtime.isWaitingForPageBreaks()` を見る。

**なぜ:** 本文をキーにすると、同じ本文が2回続いたときや、
同じブロックへロードし直したときに効果が再実行されず、
**コアが測定待ちのまま永久に止まる。**

「測定待ちのコア」と「測る UI」の待ち合わせは、本文の内容ではなく
待ち合わせの状態そのもので駆動するのが正しい。

---

## 5. 一括表示のあいだ `phase` は `waiting` のまま動かない

**決定:** 仕様として受け入れる。`type()` は文字送りをしないとき `phase` を触らない。

**なぜ:** 一括表示では本文が出た瞬間がクリック待ちであり、`waiting` は状態として正しい。
`performing` や `typing` を経由させるのは、実体のない遷移を作ることになる。

**影響:** 逐次表示を前提に「`phase` が変わるまで待つ」と書いたテストは
一括表示では即座に成立して空振りする。E2E ヘルパ `settle` / `readAll` は逐次表示専用。
一括表示を扱うテストは本文の変化で待ち合わせること。

---

## 6. 「つづきから」はタイトル画面のままロードメニューを開く

**決定:** 本編への切り替えはスロットを選んだ時点で行う。ロードが失敗したらタイトルに戻す。

**なぜ:** 先に本編へ切り替えると、スロットを選ばずに閉じたときに
何も表示されていない画面へ取り残される。戻る導線がない。

---

## 7. 開けない UI は導線ごと出さない

**決定:** バックログ・セーブ・ロード・設定のボタンは `canOpenUi()` が true のときだけ描く。

**なぜ:** 押せないボタンを出しておいて押されたら待たせる、という作りは
「いつ押せるのか」を読者に推測させる。押せる状態になってから見せるほうが単純で、
`canOpenUi()` の条件がセーブ可能点と一致していることも見た目に現れる。

engine-spec の「文字送り中に開こうとしたら文字送りを完了させてから開く」は、
結果としては満たされる（文字送り中のクリックは全文表示に使われ、
クリック待ちになった時点で導線が出る）。仕様の記述はこれに合わせて書き換えた。

---

## 8. ページ送りを踏む E2E は台本を書き換えずに作る

**決定:** Playwright で `.wn-messagebox` の `font-size` を上書きし、
既存の本文を枠から溢れさせる。ページを連結したものが元の本文と一致することまで見る。

**なぜ:** 計画は「台本に長い1行を一時的に足して確認し、あとで消す」としていたが、
台本は作品そのものであり、確認のために書き換えたくない。
また消し忘れると作品に確認用の文章が残る。

**測定の対象は変わらない。** `.wn-body` と `.wn-measure` は
どちらも `.wn-messagebox` の `font-size` を継承するため、
上書きしても両者の関係は保たれ、実装の測定経路をそのまま通る。
