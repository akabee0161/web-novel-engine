## 用語

| 用語 | 意味 |
|---|---|
| **本文ブロック** | メッセージ枠に表示されてクリック待ちになる1回分。セーブ連番の単位であり、既読ハッシュの単位 |
| **シーン** | 台本上の名前付きの区切り。セーブ位置の粗い座標であり、復元時のリプレイ開始点 |
| **スナップショット** | シーンに入った瞬間のエンジン状態。セーブの復元起点 |
| **セーブ可能点** | 本文を表示し終えてクリック待ちしている瞬間。セーブが許される唯一のタイミング |

## 基本要件

| 項目 | 仕様 |
|---|---|
| 画面形式 | ADV 型（画面下部にメッセージ枠、中央に立ち絵） |
| 分岐 | 初期実装は一本道。将来の分岐・フラグ導入に耐える設計 |
| 台本 | 1ファイル完結。無記号行＝本文、行頭 `@` ＝演出 |
| 作品規模 | 短編から始め、中長編に耐える |
| 配信形態 | 静的サイトとしてビルド・公開。サーバなし |
| セーブ保存先 | 端末ローカル |

**台本フォーマットの第一原則** — 無記号のプレーンテキストが、そのままで最小の台本として成立すること。
記法なしの原稿がパースエラーになる言語仕様は採らない。

## 起動フロー

```
URL を開く
  └→ タイトル画面（@title の文字列 ／「はじめから」「つづきから」）
       └→ ボタン押下 ＝ ユーザージェスチャ
            ├─ AudioContext を生成して resume()、無音バッファを1回鳴らして unlock
            └─ 本編開始
```

**タイトル画面は省略できない。** 音声再生の解禁がここで起きるため、
省くと iOS で BGM が鳴らない作品になる。セーブスロットの入口も兼ねる。

タイトル画面の滞在時間は、音声デコードの先読みの窓としても使える。

## 進行と表示

本文ブロックの区切りは改行。1行が1ブロックであり、クリック1回分。空行は無視される。
行がメッセージ枠に収まらない場合は自動でページ送りする（そこでクリック1回）。

**ページ分割は実行時に決まる。** 画面サイズ・文字サイズ・フォントに依存するため、
同じブロックが端末によって3ページにも1ページにもなる。
したがってページはコンパイル済み台本にもセーブデータにも一切現れず、
本文ブロック連番 `i` にも影響しない。

**文字送りの設定は2階建て。**

- モード: 逐次表示 / 一括表示
- 速度: 逐次表示のときの基準速度

台本の `@speed` は基準速度に対する**相対倍率**として働く。
読者が速度を上げていても `@speed slow` の箇所は相対的に遅くなる。

**一括表示が選ばれている間は `@speed` を完全に無視する。**
一括表示を選ぶ読者は文字が流れること自体を避けたいのであり、
そこに演出として文字送りを差し込むのは読者の意思に反する。

## コンパイル済み台本の形式

台本はビルド時にコンパイルする。既読ハッシュもこの時点で計算して埋め込む。

```json
{
  "id": "商店街",
  "steps": [
    { "t": "bg",   "name": "rain_street", "fade": 800 },
    { "t": "bgm",  "name": "rain" },
    { "t": "text", "i": 0, "h": "a3f91c22b0d4", "body": "雨は、まだ降っていた。" },
    { "t": "show", "id": "mika", "pos": "center" },
    { "t": "text", "i": 1, "h": "7e05fa19c883", "speaker": "ミカ", "body": "……帰ろうか" },
    { "t": "text", "i": 2, "h": "c1d80e4a6f37", "body": "彼女は僕の袖を引いた。" }
  ]
}
```

`i` がセーブ用の本文ブロック連番、`h` が既読用のハッシュ。
**演出ステップに `i` を振らないことが、演出行の挿入に対する耐性を生む。**

## セーブ

### 表現

セーブ位置は **シーンID ＋ シーン入口スナップショット ＋ 本文ブロック連番** で表す。

```json
{
  "scene": "商店街",
  "snapshot": {
    "bg": "rain_street",
    "bgm": "rain",
    "sprites": [{ "id": "mika", "expr": "normal", "pos": "center" }],
    "speed": "normal",
    "flashback": false,
    "vars": { "met_mika": true, "trust": 2 }
  },
  "index": 12
}
```

**`index` は「セーブした瞬間に画面に表示されていた本文ブロック」の連番。**
ロードとはセーブ時の画面を再現することであり、次のブロックから始めると
読者が最後に見ていた文が画面から消えて話が進んだ状態になる。

復元手順は「スナップショットを復元 → `0` から `index - 1` までを演出スキップでリプレイ
→ `index` を通常表示してクリック待ち」。

```
セーブ時: i:12 を表示中     → { "index": 12 }
復元:     i:0〜11 をリプレイ → i:12 を表示してクリック待ち
```

途中ページでセーブした場合、復元はそのブロックの先頭ページからになる
（ページはセーブデータに入れられないため）。読み直しは最大でも1ブロック分に収まり、
書き手が改行を入れれば短くできる。

### スナップショットの取得

シーンに入った瞬間に、エンジンの状態を丸ごとスナップショットしてメモリに保持する。
ビルド時の静的計算はしない（分岐が入ると到達経路が一意に定まらないため）。

対象は**シーン境界で持ち越される状態すべて**。
現時点では背景・BGM・立ち絵・変数・`@speed`・`@flashback`。
唯一の例外はバックログ（後述）。

### 変数はシーン入口の値を保存する

`vars` は「セーブした瞬間の値」ではなく「シーンに入った瞬間の値」。

これにより、リプレイ中に非冪等な操作を通過しても入口の値から再実行されて正しい値に着地する。
**結果としてリプレイ処理は「演出の待ち時間をゼロにするだけ」の単純な処理になり、命令の種類を区別しない。**

変数は台本側で初期値を宣言する。ロード時は「宣言済みデフォルト値にセーブ値を上書きマージ」する。
あとから変数を追加しても旧セーブは壊れない。

### 連番は本文ブロックだけを数える

`@` で始まる演出行はカウントしない。演出を何行挿し込んでも既存セーブの位置は動かない。

セーブが壊れるのは「同一シーン内に**本文ブロック**を挿入・削除したとき」だけで、
被害はそのシーン内に閉じる。

### 解決できない場合

| 状況 | 挙動 |
|---|---|
| `index` がシーンの本文ブロック数を超える | そのシーンの最後の本文ブロックにクランプする |
| `scene` が現在の台本に存在しない | ロード失敗として扱い、読者に明示する。黙って別の位置に飛ばさない |

### セーブ可能点の限定

**セーブ可能なのは「静止した画面で、次のクリックを待っている瞬間」だけ。**

- フェード中・トランジション中にオートセーブを打たない
- 演出中は手動セーブUIを開かせない
- 文字送り中にセーブが要求されたら、文字送りを完了させてからセーブする

**ページ送り待ちも含む。** 1つの本文ブロックが複数ページに分かれる場合、
途中ページのクリック待ちもセーブ可能点として扱う。画面が静止して次のクリックを
待っている点は最終ページと変わらず、下記の意図はそのまま満たされる。

復元すべき状態が「静止した画面」だけになるため、演出途中の復元という問題自体が発生しない。

## 既読

**既読は本文ハッシュの Set で持つ。セーブとは完全に独立した仕組み。**

### ハッシュの定義

入力は次の3つを連結した文字列。

```
シーン名 \n 話者名 \n 本文
```

ハッシュ関数は SHA-256、先頭12桁（48bit）。**ビルド時に計算し、実行時には計算しない。**

シーン名を混ぜるのは、「……」「うん」のような短い行が作品中で繰り返し出現するため。
本文だけでハッシュすると、序盤の「うん」を読んだ時点で終盤の「うん」まで既読になる。

（同一シーン内に同じ話者の同じ本文が複数回出る場合は依然として同一視される。
影響はスキップが1ブロック余分に進む程度なので対策しない）

### 実行時の処理

```js
readSet.add(step.h)   // 本文ブロック表示時
readSet.has(step.h)   // 既読判定
```

シーンも位置も参照しない。

### 記録タイミング

**セーブ操作とは無関係に、本文を表示した瞬間に記録する。**
セーブせずにブラウザを閉じても既読は残る。

### 改稿時の挙動

本文を書き換えるとハッシュが変わり、そのブロックだけ未読に戻る。他のブロックの既読は無傷。
本文ブロックを新規挿入した場合、以降の `i` はずれるが `h` は1つも変わらない。

## バックログ

| 項目 | 仕様 |
|---|---|
| 機能範囲 | 読み返しのみ。進行位置は動かさない（ジャンプしない） |
| 保持範囲 | 直近 N 件のリングバッファ。N は 200（調整可能な定数として1箇所に置く） |
| 単位 | 本文ブロック |
| 永続化 | しない。セッション限定 |
| 開けるタイミング | クリック待ちの瞬間だけ |

```js
backlog: [
  { speaker: "ミカ", body: "……帰ろうか" },
  { speaker: null,   body: "彼女は僕の袖を引いた。" },
]
```

既読ハッシュもセーブ連番も持たない。読み返しに必要ないため。
**バックログは既読の仕組みに一切影響しない。**

### 積むタイミング

本文ブロックを表示した瞬間。既読の記録と同じ場所に並ぶ。

```js
readSet.add(step.h)
backlog.push({ speaker: step.speaker, body: step.body })
```

**シーン境界でクリアしない。** 表示した順で 200 件を保つだけで、シーンをまたいで遡れる。

### ロード復元時のリプレイ

特別扱いしない。リプレイは「演出の待ち時間をゼロにした通常再生」なので、
通過した本文ブロックはそのまま積まれる。
結果として、ロード直後のバックログには現在シーンの先頭からの分が入っている。

### スナップショットに含めない

設計上の不変条件4の**唯一の例外**。バックログは画面の見た目を決める演出状態ではなく
単なる表示履歴であり、含めなくても復元後の画面は完全に一致する。

### 開けるのはクリック待ちの瞬間だけ

セーブ可能点とまったく同じ条件。文字送り中に開こうとしたら文字送りを完了させてから開く。
演出中（フェード・トランジション・`@wait`）は開かない。

## 音声

### 前提となる制約

| 制約 | 内容 |
|---|---|
| autoplay 制限 | `AudioContext` は `suspended` で生成され、ユーザージェスチャ内で `resume()` するまで音が出ない |
| ジェスチャの資格 | `await` を挟むとジェスチャ扱いが切れる。unlock は同期的に行う |
| iOS の音量制御 | iOS Safari は `HTMLMediaElement.volume` への代入を無視する |
| サイレントスイッチ | iOS でマナーモードが ON のとき、Web Audio の音は鳴らない |

### 再生方式

**Web Audio API に統一する。`<audio>` 要素は使わない。**

iOS Safari が `HTMLMediaElement.volume` を無視するため、`@bgm stop fade:800` が実装できない。
GainNode なら `linearRampToValueAtTime` で確実にフェードできる。

```
BGM (AudioBufferSourceNode, loop) → GainNode(bgm) ┐
SE  (AudioBufferSourceNode)       → GainNode(se)  ┼→ GainNode(master) → destination
```

システムデータに持つ音量設定が、そのまま各 GainNode に対応する。

**実装順序が制約される。** unlock はジェスチャのコールバック内で同期的に行うため、
「素材のロードを待ってから resume」ではなく「resume してから素材をロード」の順になる。

### バックグラウンド復帰

タブ切替や画面ロックで `AudioContext` は `suspended` に落ちる。二段構えで戻す。

1. `visibilitychange` で visible になったら `ctx.resume()` を試みる
2. それでも `suspended` なら、次のクリックで `resume()` する

`resume()` は冪等なので両方走っても害はない。

### `@bgm` / `@se` の意味論

| 状況 | 挙動 |
|---|---|
| 現在と同じ名前の `@bgm` が再度来た | **鳴らし直さない。** 曲頭に戻さず再生を継続する |
| 別の名前の `@bgm` が来た | 差し替える |
| ロード復元 | スナップショットの `bgm` を曲頭から鳴らす |
| `@se` | 同名でも毎回鳴らす。重なって鳴ってよい |

同名再指定で鳴らし直すと、BGM がシーンをまたいで持ち越される設計と噛み合わない。

**曲の再生位置はセーブしない。** スナップショットが「静止した画面」でなくなるため。
`@se` は状態ではなく発火なので、スナップショットの対象にもならない。

### サイレントスイッチには対応しない

iOS でマナーモードが ON のとき音は鳴らない。これを仕様として受け入れる。
OS の設定は読者の意思表示であり、エンジンが覆すべきものではない。

## ストレージ

セーブデータとシステムデータを分離する。

```
wn:<作品ID>:save:1        ┐
wn:<作品ID>:save:2        ├ セーブデータ（スロットごとに独立）
wn:<作品ID>:save:auto     ┘
wn:<作品ID>:system        ← システムデータ（作品ごとに単一・全スロット共通）
```

**システムデータの内容**

- 既読本文のハッシュ Set
- 文字送りの設定、音量などの設定
- （将来）到達したエンディングの集合、CG/BGM 回収状況

分離により、セーブスロットを削除しても既読は消えない。既読だけリセットもできる。

**`<作品ID>` は作品側が `boot()` に明示的に渡す。** ディレクトリ名から自動で拾わない。
リネームした瞬間にキーが変わり、読者のセーブが消えるため
（[実装構成](architecture.md#作品側のコード)）。

**実装方針**

- ストレージ層は差し替え可能なインターフェース越しにアクセスする
- 初期実装は localStorage
- 書き込みはメモリ上の Set を数秒おき、および `pagehide` でまとめて書き出す
- 中長編で容量が問題になったら IndexedDB に差し替える

## 設計上の不変条件

以下はコア設計を縛る条件であり、後から追加することができない。

1. **エンジンの状態はスナップショット可能な1箇所に集約する。**
   個別の演出モジュールが内部に復元不能な状態を隠し持ってはならない。
2. **シーン内のリプレイは決定論的でなければならない。**
   台本中で乱数を使う場合、乱数シードもスナップショットに含める。
3. **本文ブロックの連番は、本文ブロックだけを数える。**
4. **シーン境界で持ち越される状態は、すべてスナップショットに含める。**
   命令を追加するときは、それが持ち越す状態を持つかどうかを判断すること。
   怠ると、その演出だけ復元されないセーブができる。
   **例外はバックログのみ**（画面の見た目を決めないため）。

   構造上は `EngineState` を `snapshot` / `progress` / `view` の3層で表現する
   （[実装構成](architecture.md#状態の3層)）。スナップショットは `snapshot` 層の
   丸ごとコピーであり、対象を個別に列挙しない。新しい状態はどの層に置くかを必ず選ぶ。
   バックログが `view` にあるのが上記の例外にあたる。
   **ただし型が防ぐのは「忘れる」ことだけで、「間違える」ことは防がない。**

## 初期実装に含める / 含めない

| 要素 | 初期実装 |
|---|---|
| 既読をハッシュで表現する | 含む（連番より単純なため） |
| 既読を記録する（表示時に Set へ追加・保存） | 含む |
| 既読を使う（スキップ機能・UI） | 含まない |
| バックログ（読み返しのみ） | 含む |
| IndexedDB への差し替え | 含まない |
