## 忘れやすい前提

議論の過程で決まったが、ドキュメントを流し読みすると見落としやすいもの。

1. **セーブ可能点は「本文表示後のクリック待ち」の瞬間だけ。**
   演出途中の任意時点セーブは、解くのではなく仕様から消してある。
2. **シーンは状態をリセットしない。** 背景・BGM・立ち絵・`@speed`・`@flashback` は
   すべて持ち越される。細かくシーンを切るコストをゼロにするため。
3. **持ち越される状態はすべてスナップショットに入る。**
   命令を追加するたびにこの判断が必要。怠るとその演出だけ復元されないセーブができる。
4. **既読はセーブと完全に独立。** ハッシュの Set をシステムデータに持ち、
   本文表示の瞬間に記録する。セーブ操作とは無関係。
5. **命令を追加する条件は「台本に出てきたこと」。**
   既存エンジンにあるという理由で追加しない（`@move` はこれで一度失敗した）。
6. **バックログだけはスナップショットに入らない。** 3の唯一の例外。
   画面の見た目を決めないため。
7. **タイトル画面は省略できない。** 音声再生の解禁がここで起きる。
   省くと iOS で BGM が鳴らない作品になる。

## 残事項

### 技術スタック

未着手。静的サイトとしてビルド・公開する前提は決まっている。
フレームワーク、ビルドツール、描画方式（DOM / Canvas / WebGL）が未定。

音声については **Web Audio API を使うことが決定済み**（`<audio>` 要素は iOS で音量制御が
効かないため）。ライブラリを挟む場合も、GainNode 相当のフェードができることが要件。
