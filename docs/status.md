## 忘れやすい前提

議論の過程で決まったが、ドキュメントを流し読みすると見落としやすいもの。

1. **セーブ可能点は「本文表示後のクリック待ち」の瞬間だけ。**
   演出途中の任意時点セーブは、解くのではなく仕様から消してある。
2. **シーンは状態をリセットしない。** 背景・BGM・立ち絵・`@speed`・`@flashback` は
   すべて持ち越される。細かくシーンを切るコストをゼロにするため。
3. **持ち越される状態はすべてスナップショットに入る。**
   命令を追加するたびにこの判断が必要。怠るとその演出だけ復元されないセーブができる。
4. **既読はセーブと完全に独立。** ハッシュの Set をシステムデータに持ち、
   本文表示の瞬間に記録する。セーブ操作とは無関係。
5. **命令を追加する条件は「台本に出てきたこと」。**
   既存エンジンにあるという理由で追加しない（`@move` はこれで一度失敗した）。
6. **バックログだけはスナップショットに入らない。** 3の唯一の例外。
   画面の見た目を決めないため。
7. **タイトル画面は省略できない。** 音声再生の解禁がここで起きる。
   省くと iOS で BGM が鳴らない作品になる。
8. **`index` は「セーブした瞬間に表示していた本文ブロック」。**
   次に表示するブロックではない。ロードはセーブ時の画面の再現である。
9. **ページ送りはセーブデータに現れない。** ページ分割は実行時に端末ごとに決まるため、
   保存すると別端末で存在しないページを指す。途中ページでセーブしても
   復元はそのブロックの先頭から。
10. **作品IDはディレクトリ名から自動で拾わない。** 作品側が `boot()` に明示的に渡す。
    自動にするとリネームでストレージキーが変わり、読者のセーブが消える。
11. **演出の完了はコアのタイマーで判定する。** `transitionend` を使わない。
    使うとリプレイ（描画を伴わない高速再生）で完了を検知できなくなる。

### ドキュメントの書き分け

| 置き場所 | 役割 | 更新 |
|---|---|---|
| `docs/engine-spec.md` | 現在の確定仕様（何をするか） | 仕様が変わったら**書き換える** |
| `docs/architecture.md` | 現在の確定構成（どう作るか） | 構成が変わったら**書き換える** |
| `docs/script-syntax.md` | 台本の書き方 | 記法が変わったら**書き換える** |
| `docs/decisions/YYYY-MM-DD-*.md` | いつ何をどう決めたかの記録 | **書き換えない。** 新しい決定は新しいファイルを足す |
| `docs/status.md` | 引き継ぎ | 随時 |

**決定記録は執筆時点のスナップショット**であり、その時点で正しかった仕様を含む。
現在の仕様と食い違っていても直さない。それが記録としての価値だから。
仕様を変えたときは、新しい決定記録を足したうえで `engine-spec.md` を書き換える。
