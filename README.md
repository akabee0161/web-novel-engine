# web-novel-engine

ブラウザで動作するサウンドノベル / ビジュアルノベルエンジン。

自分が書くノベルを載せるための道具であり、想定利用者は自分ひとり。

## 目標

1. **自分の台本が実際に必要とした機能だけを作る。**
   機能の要否を決めるのは既存エンジンの機能表ではなく、自分が書いた台本。
   台本に出てこない機能は作らない。
2. **エンジンの命名はサイトブランドから独立させる。**

## 現状

**初期実装（18タスク / 6フェーズ）完了。台本の10命令すべてが動き、通しで読める。**

機能一覧から設計を起こすのではなく、先に台本を書き、そこから必要な命令セットを
確定させる方針を取っている。台本の叩き台から抽出した命令は10個で、
セーブ・既読・バックログ・音声、および技術スタックまで仕様が固まっている。

[実装計画](docs/implementation-plan.md)は 18 タスク / 6 フェーズ。
層ごとにまとめず縦に切り、**Task 7 の時点で画面が動く**ようにしたうえで、
以降は命令を1つずつパーサ・コア・UI に通しで足していく構成にしてある。

```
[完了] フェーズ1  土台と最小パーサ          Task 1-4
[完了] フェーズ2  コアの骨格                Task 5-6
[完了] フェーズ3  最小UI（ここで動く）      Task 7-8
[完了] フェーズ4  命令を1つずつ             Task 9-12
[完了] フェーズ5  既読・バックログ・セーブ  Task 13-16
[完了] フェーズ6  ページ送りと仕上げ        Task 17-18
```

動くもの: 台本（`.wn`）のコンパイル、タイトル画面、本文の文字送りとクリック送り、
話者によるネームプレートの出し分け、横持ちの 16:9 レターボックスと縦持ちの上下分割、
背景のクロスフェード、立ち絵の出入りと移動、回想の画面効果、Web Audio による BGM / SE、
既読の記録、バックログ、セーブ・ロード（リプレイによる復元）とオートセーブ、
文字送りと音量の設定、枠に収まらない本文の自動ページ送り。

**残事項**（台本に出てきていないため実装しない、README 目標1）:
素材のプリロード、スキップUI、分岐と変数、作品選択画面、
IndexedDB への差し替え、台本の複数ファイル分割、エンジン名。

次に何をするかは [現在地と残事項](docs/status.md) にある。

### 動かす

**Node 22 以上。**

```bash
NOVEL=kieta-ippen npm run dev     # 開発サーバ（NOVEL は必須）
NOVEL=kieta-ippen npm run build   # dist/kieta-ippen/ に出力
npm run build:all                 # 全作品を再ビルド

npm run typecheck && npm run lint && npm test   # コードを変えたら通す
npm run test:e2e                                # DOM に関わる変更のとき
```

### 技術スタック

| 領域 | 採用 |
|---|---|
| ビルドツール | Vite |
| UI | React + TypeScript |
| 描画方式 | DOM + CSS（Canvas / WebGL は使わない） |
| 音声 | Web Audio API |
| テスト | Vitest（ユニット） + Playwright（E2E） |

最優先事項としていた**エンジンと作品コンテンツの境界**は、
**1リポジトリに全作品を同居させ、ビルド単位を作品ごとに分ける**形で確定した。

- 作品を増やすコストは `novels/` にディレクトリを1つ足すだけ
- 作品Bを直しても作品Aは再ビルド・再デプロイしない
- エンジンを改修したときは `npm run build:all` で全作品が追従する

詳細は [実装構成](docs/architecture.md)、決定の経緯は
[技術スタックと、エンジン・作品の境界](docs/decisions/2026-08-07-tech-stack-and-boundary.md)。

一方、**作品選択画面・作品一覧UI・作品横断のセーブ管理は今も決めない。**
2作目が存在してから決めればよく、目標1（台本に出てこない機能は作らない）にも反する。

## 台本の第一原則

無記号のプレーンテキストが、そのままで最小の台本として成立すること。
記法なしの原稿がパースエラーになってはならず、演出はすべて後付けの差分である。

```
── 執筆直後（このまま動く） ──
「おつかれ。刷り上がったよ」

部長は束の一番上を持ち上げた。


── 演出と話者を足した後 ──
@bg clubroom_day fade:600
@bgm daily

>ミカ
「おつかれ。刷り上がったよ」

部長は束の一番上を持ち上げた。
```

詳細は [スクリプト構文リファレンス](docs/script-syntax.md) を参照。
